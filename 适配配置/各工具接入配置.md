# Membrane 接入各 Agent 工具配置

> 一个大脑（Membrane MCP server），接所有工具。原理：这些工具都支持 **MCP 协议**，
> 只要在它们的配置里加一段"怎么启动 Membrane"，它们就自动获得 `membrane_add` / `membrane_recall`
> 等 **10 个记忆工具**。**不需要给每个工具写插件**——这是"一套引擎适配所有工具"的关键。
>
> 所有配置里都要把 `NODE` 换成你的 node 路径、`MEMBRANE_DIR` 换成 Membrane 目录（下方一键安装脚本会自动填好）。

---

## 最快的方式：让程序帮你生成配置

不用手改占位符。编译后执行：

```bash
# 列出所有支持的客户端
membrane-memory mcp-config

# 生成某个客户端的配置（路径按你当前机器自动填好）
membrane-memory mcp-config cursor
membrane-memory mcp-config claude-desktop --out claude_desktop_config.json
membrane-memory mcp-config codex --out config.toml
```

支持的客户端（21 个）：
`claude-desktop / claude-code / cursor / cline / roo / windsurf / vscode / gemini / codex /
antigravity / continue / zed / workbuddy / zcode / astrbot / cherry-studio / lobechat /
nextchat / n8n / dify / generic`

> `--out` 写文件时，如果目标已存在会**拒绝覆盖**（避免冲掉你已经配好的其他 MCP server）。
> 这时把输出手动合并进原文件即可。

### 不想用 MCP？也可以直接走 REST

- HTTP / SDK / OpenAI Function Calling 接入：见 [`REST与SDK接入.md`](./REST与SDK接入.md)
- 现成 function schema：`openai-tools/all.json`（remember / recall / update / forget 四件套）
- 零依赖客户端示例：`examples/node-client.mjs`、`examples/python-client.py`

适合自己写 Agent、接 Dify HTTP 节点、接 LangChain、或给非 MCP 客户端用。

## 0. 先理解一件事（比喻）

把 Membrane 想成一个**记忆图书管理员**，住在你电脑里。这些 Agent 工具（WorkBuddy、Claude 等）是**读者**。
MCP 协议就是"读者怎么跟管理员说话"的统一语言。我们只在每个工具的通讯录里记下管理员的"住址和敲门方式"（就是下面那段配置），读者就能随时问管理员问题了。

---

## 通用变量（先看这里）

| 占位符 | 是什么 | 本机参考值 |
|---|---|---|
| `NODE` | node.exe 路径 | `<你的node路径>/node.exe` |
| `CLI_JS` | 编译好的入口 | `<membrane目录>/dist/cli.js` |
| `DB` | 记忆数据库文件 | `<你的数据目录>/membrane.db` |

启动命令的核心永远是这一条（所有工具殊途同归）：
```
NODE  CLI_JS  mcp
```
数据库路径通过环境变量 `MEMBRANE_DB` 指定（建议放绝对路径，别放 C 盘）。

## 1. WorkBuddy

配置文件：`%USERPROFILE%\.workbuddy\mcp.json`
（文件里可能已有别的服务配置，**追加**一项即可，不要删原有的。）

在 `mcpServers` 里加一项：
```json
"membrane": {
  "command": "<你的node路径>/node.exe",
  "args": ["<membrane目录>/dist/cli.js", "mcp"],
  "env": { "MEMBRANE_DB": "<你的数据目录>/membrane.db" }
}
```
完整的 `mcp.json` 就是多个 server 并列（原有的服务 + membrane）。
改完重启 WorkBuddy，对话框里就能看到 membrane 的工具了。

---

## 2. DeepSeek Harness

DeepSeek Harness 也是通过 MCP 接入的。**Membrane 和它是并列关系**：
两边都挂在同一个 `mcpServers` 里即可——DeepSeek 负责"思考"，Membrane 负责"记忆"，互不影响。

> 未来若想让 DeepSeek 自己直接调记忆：在它的网关配置里按同样格式加一项即可（标准 MCP）。

## 3. Claude Desktop / Claude Code

- **Claude Desktop**：配置文件 `%APPDATA%\Claude\claude_desktop_config.json`，加：
```json
"mcpServers": {
  "membrane": {
    "command": "<你的node路径>/node.exe",
    "args": ["<membrane目录>/dist/cli.js", "mcp"],
    "env": { "MEMBRANE_DB": "<你的数据目录>/membrane.db" }
  }
}
```
- **Claude Code**（命令行）：
```
claude mcp add membrane -- <你的node路径>/node.exe <membrane目录>/dist/cli.js mcp
```

## 4. Cline / Roo Code / Cursor / Windsurf / VS Code Copilot（同类）

这些编辑器插件的配置几乎一样，都是 MCP settings 里加：
```json
"membrane": {
  "command": "<你的node路径>/node.exe",
  "args": ["<membrane目录>/dist/cli.js", "mcp"],
  "env": { "MEMBRANE_DB": "<你的数据目录>/membrane.db" }
}
```
入口位置：Cline = 扩展设置里的 "MCP Servers" → Configure；Cursor = Settings → MCP；Windsurf = 同理。

## 5. Google Antigravity（反重力，Google 的 agent IDE）

它基于 VS Code 内核、支持标准 MCP。在它的 MCP 配置（workspace 的 `.gemini/settings.json` 或全局 mcp 配置）里加同样的：
```json
"mcpServers": {
  "membrane": {
    "command": "<你的node路径>/node.exe",
    "args": ["<membrane目录>/dist/cli.js", "mcp"],
    "env": { "MEMBRANE_DB": "<你的数据目录>/membrane.db" }
  }
}
```
> 注：反重力配置路径各版本可能不同；如果上面路径不对，找它的 Settings 里的 "MCP" 关键字，把同一段配置贴进去即可——**配置内容是对的，只是入口位置可能变**。

## 6. AstrBot（QQ 机器人框架，本机有）

AstrBot 原生支持 MCP，官方有 `astrbot_plugin_skills_mcp_manager` 插件管理 MCP server。
两种方式：
1. **推荐**：在 AstrBot WebUI → 插件市场装 `astrbot_plugin_skills_mcp_manager` → 添加 MCP server，填：
   - 类型：stdio
   - 命令：`<你的node路径>/node.exe`
   - 参数：`<membrane目录>/dist/cli.js mcp`
   - 环境变量：`MEMBRANE_DB=<你的数据目录>/membrane.db`
2. 或直接在 AstrBot 的 `data/config/mcp.json`（若版本支持）加同第 3 节那段 JSON。

> AstrBot 是 AGPL 协议——注意：这只是"让 AstrBot 调用 Membrane"，Membrane 本身仍是 MIT，两者通过 MCP 通信不构成代码混合。

## 6.5 zcode（智谱 GLM Coding，本机已装，格式已实测 ✅）

zcode 是智谱的 AI 编程工具（配置目录在用户目录的 `.zcode\` 下）。
它**原生支持 MCP**，但接入方式和别家不同——它是"插件包"形态：
每个插件有个 `plugin.json`，里面用标准的 `mcpServers`（command/args/env）声明工具。
我已核对它的官方插件（android-emulator / image-search）源码，格式与我们的 server 完全兼容。

**接入方法（做成 zcode 本地插件）：**

1. 在 `%USERPROFILE%\.zcode\cli\plugins\` 下建一个目录，比如 `membrane-local`。
2. 在里面建 `membrane-plugin.json`（zcode 插件清单，结构照抄它官方插件）：
```json
{
  "name": "membrane-local",
  "version": "0.2.7",
  "description": "Membrane 记忆脑：时间感知、可解释的 Agent 记忆",
  "author": { "name": "local" },
  "license": "MIT",
  "mcpServers": {
    "membrane": {
      "command": "<你的node路径>/node.exe",
      "args": ["<membrane目录>/dist/cli.js", "mcp"],
      "cwd": "<membrane目录>",
      "env": { "MEMBRANE_DB": "<你的数据目录>/membrane.db" }
    }
  }
}
```
3. 重启 zcode，它加载本地插件后，`membrane_add` / `membrane_recall` 等工具就可用了。

> ⚠️ 诚实说明：zcode 的**本地插件加载路径/开关**可能随版本变化（我实测到的是官方插件缓存在
> `cli\plugins\cache\zcode-plugins-official\`，用户级全局 MCP 入口未在 setting.json 暴露）。
> 配置内容是 100% 对的（与它官方插件同格式），**但"放哪个目录才被加载"这一入口位置请你在 zcode 设置里
> 搜"插件/MCP"确认**，或把你的 zcode 版本号告诉我，我按版本精确适配。
> 通用兜底：若插件加载不通，zcode 也支持在对话里直接说"用这个命令起 MCP server"——把上面的 command/args 给它。

## 8. 验证接好了没

接好后，对 Agent 说："**用 membrane_recall 查一下'用户住在哪'**"。
- 能返回记忆 → 成功
- 报错 → 先手动跑一遍：`set MEMBRANE_DB=... && node cli.js mcp`，看有没有红字

或者用命令行自检（不需要 Agent）：
```
set MEMBRANE_DB=<你的数据目录>/membrane.db
<你的node路径>/node.exe <membrane目录>/dist/cli.js stats
```
能打印库况就说明数据库和程序都正常。

## 9. 常见坑

| 现象 | 原因 / 解决 |
|---|---|
| Agent 看不到 membrane 工具 | 配置改完没重启 Agent；或 JSON 有语法错误（逗号） |
| 路径报错找不到 node | 路径里有中文/空格，用正斜杠 `/`，外层别漏引号 |
| 多个 Agent 同时用，数据冲突 | 不会"冲突"，但**写会排队**：SQLite 同一时刻只有一个写者，Membrane 最多等 5 秒，超时报错。读可以并发（WAL）。高频写请错峰；批量 import/回填时先停其他写入 |
| 记忆写到不同库 | 各工具的 `MEMBRANE_DB` 没统一；**所有工具都填同一个绝对路径**才能共享记忆 |
