# 关系抽取评测（规则 / 可选 LLM）

这是可复现的**回归评测**，不是“开放世界准确率”承诺。

## 为什么需要它

以前只有 doctor 里几条召回/更新剧本，规则抽取“到底抽得准不准”没有数字。  
这份评测把中文常见句式、标点、代词、否定、并列、英文负例固定成 27 条用例，改规则后跑一次就知道有没有退化。

## 怎么跑

```powershell
cd E:\开源盛世\membrane
npm run build
npm run eval:extract
# 低于阈值就失败（CI 可用）
npm run eval:extract -- --min-f1 0.9
# 机器可读
npm run eval:extract -- --json
```

## 覆盖了什么

- 住在 / 搬到 / 位于
- 在 X 工作 / 读书 / 上班
- A 是 B 的 X（同事/同学/员工/老板/妻子）
- B 的 X 是 A（反向语序）
- A 和 B 是同学/同事（对称关系）
- 喜欢 / 讨厌（含并列宾语拆分）
- 代词映射到 subject；没有 subject 时丢弃
- 中文逗号/空格间隔（“张三，住在北京”）
- 否定（“不是同学”）、无关系句、英文负例

## 可选 LLM 抽取

默认仍是规则，零依赖、零 API。需要更高质量时，在 `addAsync()` 显式打开：

```ts
await m.addAsync(
  { content: "张三是李四的同学", subject: "张三", subjectType: "person" },
  { relationExtraction: "llm" },
);
```

或在构造时默认打开：

```ts
const m = new Membrane({
  graph: { llmExtract: true, llmConfidence: 0.8 },
  llm: { baseUrl, apiKey, model: "gpt-4o-mini" },
});
```

行为：

- 手动 `relations` 永远最优先，LLM 不会被调用；
- LLM 抽到关系 → 用它，跳过规则；
- LLM 失败/返回空 → 自动回退规则，`note` 里写清楚；
- 仍然走同一条 `add()` 入库路径，不产生第二套写入逻辑；
- 不配置 LLM 时，`add()` / `addAsync()` 完全不外发。

## 已知边界

- 规则只覆盖高置信度句式，复杂句、条件句、否定嵌套、隐式关系仍会漏；
- 这份评测不测“实体类型是否 100% 正确”，只测关系三元组；
- LLM 评测目前是单元测试里的假 fetch，没有跑真实模型；真实模型的稳定性取决于你的端点；
- 27 条不足以证明开放世界质量，下一步应加入真实脱敏语料和第三方标注。
